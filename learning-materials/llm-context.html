大模型的上下文（Context）技术概念

一句话个人解释：上下文是模型在生成回复那一刻"能看见的全部信息"——系统提示、对话历史、上传的文件、工具返回的结果——装在一个容量有限的窗口里。模型没有长期记忆，它每次回答都只基于这个窗口；窗口满了，旧内容就会被挤出或裁剪，这就是一切"AI 忘事"现象的根源。

学习目标

  1. 能说出上下文窗口里通常装着哪几类内容，以及它们的排列顺序；
  2. 能解释"token"与上下文长度上限的关系，并估算一段中文大约占多少 token；
  3. 能复述"中间信息容易被忽略"现象，并给出至少两种应对策略；
  4. 能解释上下文与 Agent 工作的关系：为什么 Agent 每一步都要"写回上下文"。

核心问题

  • Q1：模型回答时"看得到"什么、"看不到"什么？（→ §4）
  • Q2：上下文窗口装满了会发生什么？（→ §5）
  • Q3：为什么塞进去的信息模型未必用得上？（→ §5）
  • Q4：上下文是如何影响 Agent 工作质量的？（→ §6，另见 agent.html）

概念定义与边界

是什么：上下文（context）指模型在单次推理中可用的全部输入信息。以 Anthropic 文档的说法，上下文窗口通常包含：系统提示（设定角色与规则）、用户消息与对话历史、附加的文档或图片、工具定义与工具调用结果等。窗口以 token 计量（中文约 1 字 ≈ 1–2 个 token，英文约 0.75 词 ≈ 1 token），不同模型的窗口从几万到上百万 token 不等。

不是什么：

  • 不是模型的"记忆"——模型参数在推理时是固定的，两次对话之间它不会记住任何东西，除非把上一轮内容重新放进窗口；
  • 不是"越大越好"的免费资源——窗口越大，成本越高、延迟越长，而且塞太满反而降低质量；
  • 不等于知识库——放不进窗口的海量知识要靠检索（RAG）按需取用。

核心机制或组成

📦 上下文窗口（容量有限，以 token 计）

⚙️ 系统提示（规则/角色） 🗂️ 附加文件 / 检索结果 🛠️ 工具定义 💬 对话历史（最早） 🗨️ 当前提问（最近）

越靠后（右）的内容离生成点越近、越容易被注意到；窗口满时，通常裁剪最早的旧内容。

  1. 无状态 + 每次重放：模型本身无记忆。所谓"多轮对话"，是应用层把历史消息拼回输入，模型每次都重新读一遍全文；
  2. token 计量与上限：输入 + 输出共同占用窗口。超出上限时请求被拒，或由应用层执行裁剪、摘要、压缩；
  3. 位置敏感（中间盲区）：论文《Lost in the Middle》通过实验发现，关键信息放在上下文开头或结尾时模型表现最好，埋在中间时召回率明显下降——长文档场景要把重点前置或收尾；
  4. 注意力稀释：窗口里无关内容越多，模型越容易被干扰（幻觉、跑题）。"上下文工程"的核心就是把最相关、最必要的内容放进去；
  5. 与外部记忆的分工：放不进窗口的知识用 RAG 检索取回；跨会话要记住的事实写入外部存储，需要时再注入窗口。

应用案例：Agent 的多步任务为什么"越走越糊"

场景：一个 Agent 帮我做一个 10 步的调研任务（对应 agent.html 的整理会议记录案例）。

走一遍流程：

  1. 第 1–3 步：每步的工具结果写回上下文，窗口还很空，模型决策准确；
  2. 第 5 步开始：早期抓取的网页全文占据大量 token，"最初的任务目标"已被挤到窗口很靠前的位置；
  3. 第 8 步：模型开始重复抓取已经看过的内容——因为任务要求已经淡出它的"视野"（位置敏感现象）；
  4. 修复方法：应用层在每轮压缩旧观察（只留摘要）、把原始目标常驻在系统提示里、限制单次抓取的全文长度。修完后 Agent 不再跑偏。

概念如何发挥作用：Agent 的"自主决策"完全发生在上下文之上。上下文里少了目标，Agent 就丢目标；塞了太多噪声，Agent 就选错工具。理解上下文 = 理解 Agent 为什么会出错、怎么修。

易混淆问题与使用边界

易混淆对区别标准
上下文 vs. 记忆（Memory）上下文是单次推理的"工作台"，会话结束即消失；记忆是跨会话持久化的信息，必须落在外部存储，用的时候才注入窗口。
上下文窗口 vs. 知识库 / RAG窗口是模型当场能"看"的；知识库在模型之外，靠检索挑出最相关片段放进窗口。RAG 是给窗口"喂料"的手段。
上下文长度 vs. 上下文质量长度是容量上限；质量是内容的相关度。实验表明塞满无关内容不如精选少量高相关内容。

使用边界（我的判断标准）：

  • 关键指令放系统提示或对话末端，别埋在长文中间；
  • 长文档优先摘要/检索，不要整篇塞窗口；
  • 多轮长任务要有主动的压缩与"重述目标"机制，不能指望模型自己记得；
  • 涉及隐私的敏感信息：一旦进入上下文就会随请求发送给模型服务方，发送前要脱敏。

自测题

1.（简答）为什么说"模型没有记忆，只有上下文"？跨会话记住用户偏好是怎么实现的？ 要点提示：无状态 + 每次重放；记忆是外部存储 + 按需注入窗口。
2.（辨析）"上下文窗口 200K token，所以我可以把 100 份文档全放进去让它自己找"——问题出在哪？ 要点提示：位置敏感与注意力稀释；成本；应改用 RAG 精选片段。
3.（简答）Agent 执行长任务时为什么要"压缩旧观察、常驻任务目标"？ 要点提示：窗口容量有限 + 中间信息易被忽略（Lost in the Middle）。
4.（估算）一篇 3000 字的中文文档大约占多少 token？会不会挤占窗口？ 要点提示：中文约 1 字 ≈ 1–2 token，即约 3000–6000 token，长对话中占比可观。
