Agent（智能体）技术概念

一句话个人解释：Agent 是一个以大模型为"大脑"、能围绕目标自主感知环境、规划步骤、调用工具并根据结果不断调整行动，直到完成任务的系统。它和普通聊天机器人的本质区别是：聊天机器人回答问题，Agent 办成事情。

学习目标

  1. 能用一句话向别人说清 Agent 和普通 LLM 应用（如问答机器人）的区别；
  2. 能画出 Agent 的基本循环：感知 → 规划 → 调用工具 → 观察结果 → 再决策；
  3. 能举出一个具体场景，说明哪些环节该交给模型自主决策、哪些该用固定工作流；
  4. 能解释"工作流（workflow）"与"智能体（agent）"的分界标准。

核心问题

  • Q1：为什么有了大模型还需要 Agent？（→ §5）
  • Q2：Agent 靠什么机制"自主"起来？（→ §5）

  • Q4：Agent 和 Workflow、Chatbot 怎么区分？（→ §7）

概念定义与边界

是什么：Agent 是由 LLM 驱动、在运行时自主决定执行路径的系统。它拥有工具（如搜索、代码执行、文件读写），围绕一个目标迭代"行动—观察—再行动"，直到任务完成。Anthropic 在《Building effective agents》中给出的分界是：如果应用程序只是预先编排好代码路径调用模型，那是工作流；如果由模型自己动态决定过程和工具使用，那才是 Agent。

不是什么：

  • 不是"更大的模型"——Agent 是一种系统架构，不等于模型本身；
  • 不是任何带工具调用的程序——路径由写死的代码决定的是工作流；
  • 不是万能自动机——它依赖明确的任务目标和足够的信息，目标含糊时表现会显著下降。

核心机制或组成

我的理解：Agent = 模型（大脑）+ 工具（手脚）+ 记忆/上下文（工作台）+ 循环（工作方式）。四者的协作方式如下：

🎯 目标→ 🧠 LLM 规划→ 🔧 调用工具→ 👀 观察结果↺ 反馈回 LLM 再决策

Agent 的基本循环：LLM 决定下一步 → 执行 → 把结果放回上下文 → 再决策，直到任务完成

  1. 模型即决策者：LLM 根据当前上下文（目标、已有结果、工具说明）判断下一步做什么，这是"自主性"的来源；
  2. 工具调用（Tool Use）：Agent 通过结构化接口调用搜索、代码执行、API 等外部能力，工具的描述质量直接决定 Agent 用得好不好；
  3. 上下文管理：每一步的观察结果都要写回上下文，供下一轮决策使用——这正是"大模型的上下文"概念发挥作用的地方（见 llm-context.html）；
  4. 迭代循环与终止条件：循环持续到任务完成或触发停止条件（步数上限、检查点、人工确认），防止无限执行；
  5. 编排层（Orchestrator）：复杂任务可拆给多个子 Agent 协作，由编排者分配、汇总。

应用案例：自动整理一周的会议记录

场景：我想让 Agent 把散落在邮箱和聊天工具里的一周会议记录整理成纪要。

走一遍流程：

  1. 我给出目标："找出本周 5 场会议的记录，各提炼 3 条要点和待办事项，汇总成一个文档"；
  2. Agent 的 LLM 规划：先搜索邮箱 → 调用邮件工具拿到 5 封邮件 → 发现第 4 场会议的记录在聊天工具里，再调用聊天工具获取；
  3. 对每份记录调用摘要能力提炼要点，把中间结果写回上下文；
  4. 发现第 4 场的记录里没有明确的待办事项，Agent 根据讨论内容自行归纳，并标注"待办为推断，请确认"；
  5. 调用文档工具生成汇总，附上来源索引，完成任务并汇报。

概念如何发挥作用：第 2、4 步里"路径是模型临场决定的"（记录可能在哪个系统、缺数据时怎么办），这就是 Agent 区别于固定脚本的关键。如果所有步骤都能预先写死，就不需要 Agent，用工作流更便宜、更可控。

易混淆问题与使用边界

易混淆对区别标准
Agent vs. Workflow（工作流）Workflow 用代码预先编排 LLM 的调用路径，可预测、成本低；Agent 让模型运行时自己决定路径，灵活但成本与不确定性更高。能用 Workflow 解决就不要上 Agent。
Agent vs. Chatbot（聊天机器人）Chatbot 的产出是"回答"，一轮一答；Agent 的产出是"完成的事"，包含多轮行动与工具调用。
Agent vs. 多 Agent 系统单 Agent 是一个决策循环；多 Agent 是多个循环协作（分工/评审/接力），复杂度上升，只在单 Agent 明显不够时才引入。

使用边界（我的判断标准）：

  • 任务目标明确、可验证（有清晰的"完成"标准）时才适合 Agent；
  • 环境可被工具访问（文件、API、浏览器），否则 Agent 无"手脚"可用；
  • 允许一定成本与延迟，且有止损机制（步数上限、人工审批、沙箱权限）；
  • 高风险操作（发邮件、付款、删数据）必须设置人工确认检查点。

自测题

1.（辨析）"一个会调用搜索工具的 LLM 应用一定是 Agent"——对吗？ 要点提示：从"路径由谁决定"入手：写死代码决定调用时机 vs. 模型运行时自主决定。
2.（简答）为什么说"工具描述的质量直接决定 Agent 表现"？ 要点提示：模型只能依据工具的说明来决定何时用、怎么用；说明含糊会引发错误选择。
3.（简答）设计一个客服 Agent，哪些步骤该用固定工作流，哪一步才值得用 Agent？ 要点提示：身份核验、工单分类等固定环节用工作流；需要跨系统查证据、临场决策的处理环节才用 Agent。
4.（开放）给 Agent 加"步数上限"和"人工确认"分别防住了什么风险？ 要点提示：无限循环与成本失控；高风险外部动作（发消息/删数据）不可逆。
